## 2. 思想と想い（Philosophy / Vibe）

* **「装飾としてのノイズ」の完全否定**
  * 映像を加工して後からグリッチを乗せるのは、情報システム的な「偽造」である。
  * 無加工の映像の「ありのままの事実（データ）」を、音を歪ませる「物理的な配管（LFO）」として直接流し込む。
* **「レコードの物理制約」への回帰**
  * 無限のグラデーションを許さず、33rpmと45rpmという「アナログレコードの物理的な回転数」に強制的にカチッと切り替える（クオンタイズする）。
  * 現場のノイズ（映像の動き）をトリガーとして、レコードの物理ボタンを乱暴に切り替えるような「意図のある狂ったグルーヴ」を生み出す。
* **ローカル主権の確立**
  * この配管はクラウドAIには作れない。手元のローカル環境（Apple Silicon / OpenCV / atoTerminal）だからこそ実現できる、映像と音の「データレベルでの完全な同期」である。

## 3. アイデアとアーキテクチャ（Idea / Architecture）

### ツール名

`turntable-lfo-extractor`（抽出器） + `Turntable LFO`（VST3 プラグイン）

### 入力と出力

* **入力**: 無加工の動画ファイル (.mp4, .mov)
* **出力**: ステップLFOデータ (.json / .mid)
  * 配列の中身は `[33.3, 45.0, 33.3, 33.3, ...]` のように、BPMグリッドに合う解像度で刻まれた数値データ。

### 処理フロー（ハード制約の配管）

1. **運動量抽出（Optical Flow）** — `turntable_lfo/motion.py`
   * OpenCV (`cv2.calcOpticalFlowFarneback`) を使用し、フレーム間の動きの激しさ（Motion Energy）を1次元の連続値配列として取得する。
2. **LFOクオンタイズ（ハードスナップ）** — `turntable_lfo/quantize.py`
   * 連続値をそのまま使うことを禁止し、Schmitt トリガ（2閾値）で強制的に離散RPM値へ丸め込む。
     * `motion < THR_LOW` → `0.0`（テープストップ / 完全静寂）※オプション
     * `THR_LOW <= motion < THR_HIGH` → `33.333`（33rpm / ピッチダウン -5.36半音）
     * `motion >= THR_HIGH` → `45.0`（45rpm / 等倍）
3. **ダウンサンプリングと平滑化（BPM同期）** — `turntable_lfo/quantize.py`
   * 映像FPSはLFO解像度として細かすぎるため、BPMグリッド（例: 16分音符）にダウンサンプリングする。
   * ヒステリシス（状態保持 / 最小ホールド長）で「1フレームだけ45rpm」のチャタリングを防ぎ、「カチッ、カチッ」という切り替え間隔を担保する。

## 4. アーキテクチャ決定記録（ADR）：なぜ「抽出器(Python) + VST(JUCE)」に分割するか

当初の設計書は Python CLI 単体を想定していたが、最終形を **VST** とするにあたり、実行モデルを2層に分離する。

* **事実**: VST はリアルタイムのオーディオスレッド上で動作する。映像のデコードとオプティカルフロー計算をオーディオコールバック内で行うのは、フレーム同期不能・バッファアンダーラン（xrun）を招き破綻する。
* **結論**: 映像解析は **本質的に前処理（オフライン）** である。

| 層 | 実装 | 責務 |
|---|---|---|
| 抽出器 | Python + OpenCV (`extractor/`) | 映像 → motion energy → ハードスナップ → BPMグリッドの `.json` |
| エンジン | JUCE VST3 (`vst/`) | `.json` を読み込み、ホスト transport に同期してヴァリスピード変調（または内部エンベロープ駆動）を適用 |

### RPM とピッチの関係（事実）

ターンテーブルの回転数変更は再生速度（=ピッチ＝タイム）を同時に変える。基準を 45rpm に取ると、

```
ratio        = rpm / 45
33.333 / 45  = 0.74074
semitones    = 12 * log2(0.74074) = -5.36 半音
```

VST 側のヴァリスピードは、リングバッファの読み出しレートを `rpm / ref_rpm` に設定して実現する（レート < 1 で遅延が蓄積する＝物理ターンテーブルと同じ挙動。バッファ長でクランプする）。

## 5. atoTerminal への統合（Layer C: 行動層）

`extractor/turntable_lfo/cli.py` を atoTerminal のツールとして組み込む。

**利用イメージ:**

```bash
> @video.mp4 の動きからLFOを抽出して。閾値は少し高めで、アクションシーンだけ45rpmになるように。
```

エージェントは動画の尺・内容に応じて閾値を推論し、CLI を叩いて DAW 用 LFO データ（`.json`）を生成 → VST がそれを読み込む。
